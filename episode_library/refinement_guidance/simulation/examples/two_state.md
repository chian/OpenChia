# A two-state simulator with an exact reference

Illustrative, unexecuted example. It supplies a small model with independently
inspectable expectations, not evidence for a shipped simulation Episode.

## Model and exact answer

State is 0 or 1. Start at 0. At each step independently draw an integer uniformly
from `{0, 1, 2, 3}`. Use this transition rule:

- From 0, draw 3 moves to 1; the other draws remain at 0.
- From 1, draws 0 or 1 move to 0; draws 2 or 3 remain at 1.

Rows and columns of the transition matrix are ordered `(0, 1)`:

```text
P = [[3/4, 1/4],
     [1/2, 1/2]]
```

The probability of state 1 after two steps is
`(3/4)(1/4) + (1/4)(1/2) = 5/16`.
Equivalently, among the 16 equally likely ordered draw pairs, three reach 1 by
staying at 0 then switching, and two by switching then remaining at 1.

The stationary state-1 probability is `1/3`, obtained from
`p = (1-p)/4 + p/2`. It is **not** the two-step answer. This distinguishes a
transient calculation from a plausible but wrong steady-state substitution.

## Local implementation measure

The coding child receives fixed checks for all eight state/draw transitions,
the initial condition, legal states, and all 16 two-draw trajectories. The checker
uses the explicit table above, not values generated by the candidate.

These checks can reject an always-zero simulator, swapped matrix rows, treating
state 1 as absorbing, and using the new state twice within one step. They establish
the declared finite transition mapping and short-horizon driver, not the quality
or independence of a random generator.

## Parent acceptance example

A proposed protected check combines the deterministic mapping with a separately
declared stochastic check. For example, run 4096 independent two-step replicates
using an admitted random-input implementation and a precommitted stream policy.
Let K count replicates ending at 1. Under the model, `K ~ Binomial(4096, 5/16)`.

Before execution, the independent verifier derives central acceptance limits
from that exact distribution with each rejection tail at most `0.005`. Preserve
K, the input/stream identity, the calculated limits and the decision. Passing
means no contradiction under this particular procedure, not a proof of general
distributional correctness. Correct implementations can fail a stochastic check
with its declared error probability; the result must be interpreted accordingly.

Do not retry seeds until passing or treat adjacent steps from one trajectory as
4096 independent replicates. Repeated checks or broader distributional claims
need their own frozen sampling/error policy. The number 4096 is an illustrative
instrument setting, not an Episode completion budget or a recommended universal
sample size.

## What remains outside this example

The parent must admit the statistical procedure, generator, independence
assumptions and applicable scope before use. More states, continuous time,
dependent randomness, long-run claims and real-world model validity require new
grounding. No generated trajectories or test outcomes are claimed here.
